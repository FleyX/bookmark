# 权限与资源以 YAML 注册表为唯一定义，不落库

角色权限体系采用 jcloud 已验证的同构方案：权限（permission）与资源（resource）的唯一定义来源是后端 `permissions.yml`（启动时 fail-fast 校验并加载进内存注册表），数据库只存角色表和「用户↔角色」「角色↔权限 code」两张绑定表。

**Considered Options**

- YAML 注册表（选用）：定义即代码、随版本演进、启动即发现登记遗漏或格式错误；代价是每加一个受控接口需手工登记并重启。
- 权限/资源全部落库：运行时可在管理页维护资源，更灵活；但实现量大约翻倍，且资源随环境漂移（各环境数据可能不一致），与本系统"接口集合由代码决定"的现实不符。

**Consequences**

- 原 url 表的公共 URL 机制随之废弃，免登录接口移入 `permissions.yml` 的 public 段。
- `manageUserId` 配置及其 3 处硬编码管理员校验被角色鉴权取代。
- 角色绑定的是权限 code 字符串而非 id；YAML 中删除某权限后，存量绑定成为悬空引用，解析时静默忽略。
- 新增受控接口漏登记 = 非超管一律 403（fail-closed，刻意为之）。
