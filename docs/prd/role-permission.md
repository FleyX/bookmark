# PRD: 角色权限体系与用户管理

状态：已确认（访谈收敛于 2026-10-14）
关联 ADR：[0001-permission-yaml-registry](../adr/0001-permission-yaml-registry.md)

## Problem Statement

签签世界目前没有任何角色/权限概念：全系统只有一个由配置项 `manageUserId` 指定的"管理员"，且仅守护 3 个运维批处理接口；其余所有接口对登录用户一视同仁。随着系统演进，需要：

1. 一套可扩展的角色权限体系——后端管控到 URL 级，前端管控到页面级；
2. 一个管理后台，让管理员能管理用户（禁用、重置密码、分配角色）和角色（定义角色、绑定权限）。

## Solution

移植 jcloud 已验证的方案：权限与资源定义在 `permissions.yml` 注册表（不落库），数据库只存角色及两张绑定表；登录过滤器升级为"公共 → 登录 → 角色资源"三段式鉴权；前端新增 `/admin` 管理后台，按登录接口下发的资源列表过滤路由与菜单。

- 内置 `super_admin` 角色，按角色 code 判定，拥有全部权限（后端短路放行、前端视为全量资源），不可编辑/删除/禁用。
- 全新部署：**首个注册用户**自动绑定 super_admin；存量部署：迁移把最早注册（userId 最小）的用户绑定为 super_admin。README 中说明此规则。
- 旧 `manageUserId` 配置与 url 表公共 URL 机制一并废弃。

## User Stories

1. 作为**站长（首个注册用户）**，我希望注册后自动成为超级管理员，以便无需任何手工配置即可使用管理后台。
2. 作为**超级管理员**，我希望我的请求在后端直接放行，以便新增权限点无需给我重新授权。
3. 作为**管理员**，我希望在管理后台看到用户分页列表并能按用户名/邮箱搜索，以便定位目标用户。
4. 作为**管理员**，我希望查看用户详情（含书签数等统计），以便了解用户使用情况。
5. 作为**管理员**，我希望禁用/启用用户账号，以便制止违规使用；被禁用户最长 60 秒内无法继续使用，登录时看到"账号已被禁用"。
6. 作为**管理员**，我希望重置用户密码，以便协助无法自助找回的用户；重置后该用户旧 JWT 失效。
7. 作为**管理员**，我希望给用户分配/回收角色（多对多，权限取并集），以便灵活授权。
8. 作为**管理员**，我希望创建/编辑/禁用/删除自定义角色，并为其勾选权限树，以便按职责划分权限。
9. 作为**管理员**，我希望禁用角色立即对已绑定用户生效，以便及时回收权限。
10. 作为**管理员**，我希望有用户绑定的角色不能被删除，以避免误操作造成权限悬空。
11. 作为**管理员**，我希望角色变更后相关用户的权限立即生效，以便授权操作可即时验证。
12. 作为**管理员**，我希望现有 3 个运维接口（全量拼音重建、全量图标更新、问题书签处理）由 `ops:bookmark` 权限守护，以便这些能力随角色体系分发。
13. 作为**有权用户**，我希望在首页底部看到"管理后台"链接，以便进入管理后台；无权用户不看到该链接。
14. 作为**有权用户**，我希望管理后台左侧菜单只显示我有权限的页面，无权限页面访问时跳 403，以便界面与能力一致。
15. 作为**普通用户**，我希望书签、目录、个人中心等存量功能完全不受权限体系影响（登录即可），以便使用体验无变化。
16. 作为**插件用户**，我希望浏览器插件的登录与添加书签流程零变化（JWT 结构与两个契约页不变）。
17. 作为**开发者**，我希望新增受控接口时在 `permissions.yml` 手工登记资源、启动即校验遗漏与格式错误，以便授权面始终明确且 fail-closed。
18. 作为**访客**，我希望登录、注册、验证码、重置密码、OAuth、全局配置、Pin 等接口保持免登录，以便注册登录流程不变。

## Implementation Decisions

**总体架构**（ADR 0001）：权限/资源唯一定义在 `permissions.yml`，启动加载进内存注册表并 fail-fast 校验（资源 code 全局唯一、格式合法、父权限存在、树无环）；数据库仅存角色与绑定。

### 后端（bookMarkService）

- **permissions.yml 三段结构**：
  - `public`：免登录资源（现有 8 个公共 URL 平移）
  - `login`：登录即可的显式声明（语义锚点；未列入 public 且未列入权限树的接口默认登录即可）
  - `permissions`：权限树，节点含 `code`/`name`/可选 `parent`/内嵌 `resources`；绑定子权限时沿 parent 链展开获得祖先资源
- **资源 code 格式**：`METHOD:路径`（后端接口）或 `VIEW:路径`（前端页面），Ant 风格通配比对
- **初始权限树**：
  - `system:user` → `VIEW:/admin/user` + 用户管理全部接口
  - `system:role` → `VIEW:/admin/role` + 角色管理/权限树查询接口
  - `ops:bookmark` → 3 个批处理接口（收编 manageUserId 守护的接口）
- **V27 迁移**：新建 `role`、`user_role`、`role_permission` 三表（无外键，角色绑权限 code 字符串）；内置 `super_admin` 角色行；将 userId 最小的存量用户绑定 super_admin；url 表停止使用（表保留不删，代码移除引用）
- **鉴权链路**：登录过滤器升级为三段式——public 放行 → JWT 校验（附加 Redis 禁用/密码版本标记检查）→ 角色资源 Ant 匹配，不匹配返回 403；super_admin 角色 code 短路放行
- **JWT 吊销**：禁用账号、管理员重置密码时写 Redis 标记；过滤器校验 JWT 时查标记（用户态进程内缓存 TTL 60s）
- **权限缓存**：用户→资源 code 解析结果进程内缓存，角色/绑定/权限变更时主动失效（单实例部署前提）
- **模块归属**：权限注册表/解析/缓存放 `common`（过滤器需要）；角色管理、用户管理扩展放 `business/user`；`UserApi` 按需扩展（如书签统计）
- **配置变更**：删除 `manageUserId` 配置及 docker-compose 对应 `-D` 传参；删除 3 处 `getManageUser()` 硬编码校验
- **接口契约**：
  - `GET /user/currentUserInfo` 响应新增 `resources` 字段（当前用户已展开的资源 code 列表）
  - 用户管理接口：分页列表+搜索、详情（含书签统计）、启用/禁用、分配角色、重置密码
  - 角色管理接口：分页/全部列表、详情、增、改、删（有绑定禁止）、禁用/启用、绑定权限（全量替换）
  - 权限接口：权限树只读查询（供角色编辑页渲染勾选树）
  - JWT 负载不变（仅 userId）；注册接口在"库中无用户"时为新用户绑定 super_admin（并发安全由注册唯一约束与事务保证）

### 前端（bookmark_front）

- 新增 `/admin` 顶级路由与独立管理布局：左侧栏（顶部 logo，中部按权限过滤的菜单：用户管理/角色管理，底部当前用户头像/昵称 + "返回书签"），右侧正文
- 路由元信息声明所需 `VIEW:` 资源；路由守卫在登录后按 `resources` 过滤动态路由，无权限访问受保护页跳 403 提示页
- home 页底部增加"管理后台"链接，仅登录且拥有任一 `VIEW:/admin/*` 资源的用户可见
- 用户管理页：搜索、分页表格、详情抽屉（含书签统计）、启用/禁用、分配角色、重置密码
- 角色管理页：角色列表、新建/编辑（权限树勾选）、禁用/启用、删除（后端拦截有绑定删除）；super_admin 行只读
- 存量路由、布局、两个插件契约页（`/noHead/addBookmark`、`/manage/sso/auth`）不变

### 文档

- `README.md` 新增"管理员与权限"小节：首个注册用户即超管、权限模型与 permissions.yml 维护规则
- `docker-compose.yml` 移除 `manageUserId` 传参

## Testing Decisions

**测试缝**（与用户确认过）：

1. **后端 service 层纯单测**（存量强制缝，JUnit 5 + Mockito）：角色管理、用户管理（禁用/重置密码/分配角色）、权限解析器——DAO/Redis/跨模块 Api 全部 mock。验证外部行为：禁用立即生效、有绑定禁止删除、super_admin 保护、权限并集展开、首个注册用户绑定超管等。
2. **鉴权过滤器单测**（同一缝的延伸）：mock request/response/注册表，覆盖 public 放行、未登录拒绝、登录即放行、资源匹配/不匹配、super_admin 短路、禁用标记拦截。
3. 前端无测试设施，不新增；以 `pnpm build` + `pnpm lint` 全绿 + 手工走查为验收。

**先验**：`bookMarkService` 各 business 模块现有 `*ServiceImplTest`（JUnit5+Mockito 纯单测风格）；jcloud 同构实现可作行为参照。

**验收**：`mvn clean install`、`pnpm build`、`pnpm lint` 全绿。

## Out of Scope

- 删除用户（涉及书签数据处置，本期不做）
- 按钮/字段级权限（前端只到页面级）
- 权限/资源的运行时在线编辑（定义即代码，改 YAML 需重启）
- 多实例部署的权限缓存广播（单实例前提）
- 普通用户自助修改密码的 JWT 吊销（仅管理员重置密码触发吊销）
- 浏览器插件的任何改动

## Further Notes

- 悬空绑定（角色绑了 YAML 中已删除的权限 code）解析时静默忽略，启动时打 warn 日志提示清理。
- `permissions.yml` 与控制器路径之间无编译期校验，路径写错只能运行期发现——登记时注意与 `@RequestMapping` 逐字核对。
- user PO 中残留的 `searchEngineId` 字段（DB 无对应列）本次顺手清理。
